# Mac 官方 UU 双向互通：云真机历史执行记录

日期：2026-10-20（Asia/Shanghai）。**云端仅验证临时诊断应用的上传、签名与启动前置条件，没有取得完整互通验收。后续用户改为在本地官方 2in1 模拟器推进第 1、3 项，二者已完成本地验收；第 2 项反向被控暂缓。** 最新结果见[本地 Mac 稳定性与电脑分组](2026-10-20-本地Mac稳定性与电脑分组.md)。本记录保留云端阶段的失败与限制，不将本地结果表述为云真机通过。

## 云端阶段的原定范围

1. 鸿蒙电脑控制 Mac 官方 UU：20 分钟持续连接、20 次普通重连，分别验证画面、鼠标、基础键盘及主动断开。
2. Mac 官方 UU 控制鸿蒙电脑：实时画面、鼠标、基础键盘，以及断开和撤销授权后的停止行为。
3. 鸿蒙设备在官方 Mac UU 中实际显示于“电脑”分组，不以改名或伪造可控状态替代。

## 起始排查事实

- 历史 Mac 模拟器基线在四次 `KEY_REFRESH_OK` 后仍发生约 17 分 48 秒的心跳中断；20 次普通重连有两次失败。继续增加刷新次数没有已证实的修复依据。
- 当时原生 polling 每次创建 HTTP 请求并强制 HTTP/1.1、`Connection: close`，用于避免应用内 DNS 路由变化后复用旧节点连接。慢 POST 可能占住 Engine.IO 串行发送队列，后续 pong 需要等待；不能违反协议并发 POST 或在语义不明时重放。
- `2300028` 的约 15 秒耗时与当时连接期限一致；`2300052` 为空响应。仅凭错误码不能判定 DNS、TCP、TLS、代理或服务端哪层是根因。
- 起始版本使用 `/api/v1/device/android/init`、平台头 `2`，已有 `deviceId` 会跳过初始化；仅改设备名称无法改变分组，桌面身份修正还需迁移旧身份。
- 定向静态核对关联了官方 Mac 初始化的 POST 方法、`/api/v1/device/macos/init`、JSON 正文、平台头 `4`，响应设备键为 `device_id`。正文含 `controllable`，不得为分组伪造可控能力。静态证据本身不证明 HarmonyOS 资料被服务端接受。
- 当时产品没有被控上线或媒体发送链路；独立被控能力探针 0.0.2 已准备，但未上传或安装云设备。

静态来源保存在本机忽略目录 `.local/research/2026-10-20-macos-device-init.md`。没有读取官方客户端账户凭据或降低 TLS 验证；后续本地修复与验证另见最新验收文档。

## 当时的诊断准备与离线验证

增加原生 polling 非敏感编号与 START、HEADERS、SUCCESS、ERROR 阶段日志。成功响应中的 DNS/TCP/TLS/发送/接收时间标为从请求开始的累计毫秒；API24 可选连接信息只记是否复用、代理或缓存，不记地址、URL、Header、Cookie 或认证值。本阶段没有改变超时、重试、HTTP/1.1、Connection close 或恢复语义。

当时 transport 63 项、policy 221 项、signing 32 项及 session 检查通过，覆盖非法 timing 不外泄、API23 缺省字段、observer 失败兼容、取消与页面代际隔离。后续窄范围复核 Web 49/49、transport 63 项通过，未发现足以解释历史掉线的确定清理竞态。这些离线结果不能替代云端故障时序。
