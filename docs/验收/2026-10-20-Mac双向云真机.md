# Mac 官方 UU 双向互通：云真机执行记录

日期：2026-10-20（Asia/Shanghai）。本记录对应用户已确认并授权自动执行的三个目标；目标仍在进行中，以下准备与离线检查不构成云真机验收。

## 本轮范围与顺序

1. 优先修复鸿蒙电脑控制 Mac 官方 UU 的长连接掉线、主动断开后重连失败、异常断线后重连失败；在鸿蒙电脑云真机完成既有 20 分钟持续连接和 20 次普通重连基线，并分别验证画面、鼠标、基础键盘和主动断开。
2. 第一项通过后实现 Mac 官方 UU 控制同一鸿蒙电脑云真机，分别验证实时画面、鼠标、基础键盘、断开及撤销授权后的停止行为。
3. 修正该鸿蒙设备在 Mac 官方 UU 中的分组，以官方客户端实际显示在“电脑”分组为准。

云真机控制台仅使用 Codex 内置浏览器。本轮不使用日常 Chrome/Safari 操作云真机，不抢占用户系统输入，不强制接管活动远控。`AGENTS.md` 中“当前任务先在 Mac Studio 的官方 2in1 模拟器实现与验证”由用户本轮更具体的“正向和反向都用鸿蒙电脑云真机验证”取代；既有模拟器记录仅作历史基线。

## 已确认的排查事实

- 既有 Mac 模拟器记录在四次 `KEY_REFRESH_OK` 后仍出现约 17 分 48 秒的心跳中断；20 次普通重连有两次失败。会话刷新已实现，尚无证据说明继续增加刷新能够解决当前故障。
- 原生 polling 每次创建 HTTP 请求并强制 HTTP/1.1、`Connection: close`，用于避免 App DNS 路由变更后复用旧节点连接。慢 POST 会占住 Engine.IO 的串行发送队列，后续 pong 需要等待；不能违反协议并发 POST 或在未确认语义时重放。
- 历史 `2300028` 的约 15 秒耗时与当前连接期限一致；`2300052` 记录为空响应。仅凭这些数值不能判定 DNS、TCP、TLS、代理或服务端哪层是根因。本轮先补脱敏阶段观测，不将候选机制写成已确认根因。
- 当前设备初始化调用 `/api/v1/device/android/init`，请求头平台值固定为 `2`。设备名称包含 HarmonyOS 不能改变该请求身份；已有 `deviceId` 会跳过初始化，因此后续桌面身份修正还需要处理旧身份迁移。
- 官方 Mac 二进制包含 `/api/v1/device/macos/init`、`desktop_devices`、`mobile_devices`。静态路径和字段元数据不证明完整桌面注册协议，也不能证明修改单个字段即可进入电脑分组。
- 本地 0.0.2 被控媒体诊断包仍存在，SHA256 与既有记录一致；本轮尚未上传或安装。当前产品仍没有被控上线和媒体发送链路。

## 诊断准备与离线验证

本轮只增加原生 polling 诊断，未改变 HTTP/1.1、Connection close、超时、重试或断线恢复语义。每个 polling 请求使用跨页面代际递增的非敏感序号，记录 START、HEADERS、SUCCESS、ERROR；成功响应中的 DNS/TCP/TLS/发送/接收等时间明确标为从请求开始的累计毫秒。API24 可选连接信息仅记录是否复用、是否代理、是否缓存，不记录地址、URL、报文、Header、Cookie 或认证值。

新增测试先因缺少编号 START 记录失败，再实现诊断后通过。现有原生离线检查结果：transport 63 项、policy 221 项、signing 32 项、session 检查全部通过；覆盖非数字 timing 不外泄、API23 缺省字段与 observer 注册失败兼容、旧代际/已取消请求迟到时不误记新故障。`git diff --check` 通过。
