# 架构与安全边界

本文说明当前主控实现及维护时应保留的边界。安装、配置见 [README](../README.md)，实测能力及限制见[兼容性与验证结果](兼容性与验证结果.md)。本应用独立开发，连接本人账号下的官方 UU Mac / Windows 客户端；没有实现鸿蒙被控端，也不以自建被控服务替代官方客户端。

## 组件分工

| 组件 | 责任 | 源码入口 |
| --- | --- | --- |
| ArkTS Stage / ArkWeb 容器 | 加载可信本地资源、管理页面代际、原生桥和窗口 | [Index.ets](../entry/src/main/ets/pages/Index.ets) |
| 原生网络桥 | HTTPS、应用内信令 DNS 规则、请求取消和受限诊断 | [NativeBridge.ets](../entry/src/main/ets/bridge/NativeBridge.ets)、[NetworkPolicy.ets](../entry/src/main/ets/bridge/NetworkPolicy.ets) |
| HUKS / AssetStoreKit | 协议签名材料与安全登录态，二者分别管理 | [SigningMaterial.ets](../entry/src/main/ets/bridge/SigningMaterial.ets)、[SessionStore.ets](../entry/src/main/ets/bridge/SessionStore.ets) |
| TypeScript 页面 | 登录、设备选择、连接动作与输入界面 | [main.ts](../web/src/main.ts)、[uuClient.ts](../web/src/uuClient.ts) |
| 信令与媒体 | 原生 polling 适配、Socket.IO、WebRTC 和数据通道输入 | [signalClient.ts](../web/src/signalClient.ts)、[remoteSession.ts](../web/src/remoteSession.ts) |

ArkWeb 只加载打包的本地资源，关闭 DOM Storage、数据库、文件访问和网页调试，阻止外部页面导航与混合内容；SSL 错误直接取消。原生桥只接收受限 JSON 操作，不接受任意代码、系统 API 名称或通用网络代理请求。

## 协议流程与设备身份

正常流程为：本机签名材料 → 桌面初始化 → 本人短信登录或安全恢复 → 本人设备列表 → 加入房间 → 信令连接 → control 确认 → SDP/ICE → 视频与控制数据通道 → 主动断开及房间清理。

桌面初始化使用 `/api/v1/device/macos/init`，协议平台值为 `4`。这是与现有 UU 桌面接口兼容的注册类别，资料中的系统、型号、分辨率与 DPI 仍来自真实 HarmonyOS 信息；无法确认的 CPU、内存及 Mac 专属字段留空，`controllable=false`，不虚构被控能力。

旧 Android 注册身份不能跳过桌面初始化；迁移使用稳定安装 UUID 派生新的桌面 client ID。初始化成功后保存桌面标记及新设备 ID，失败不覆盖或删除旧安全会话。参见 [uuClient.ts](../web/src/uuClient.ts)。

界面以已注册的本端设备 ID 精确识别 HarmonyOS 图标；其他设备按已知平台 `4` / `1` 显示苹果 / Windows 图标，不根据可编辑名称猜测系统。图标分类不改变连接权限，参见 [devicePresentation.ts](../web/src/devicePresentation.ts)。

连接入口仅开放本人列表中允许控制的 Mac / Windows，未知平台不可连接。普通加入使用 `force_join:false`；只有业务 2002 返回且用户明确点击接管入口时才允许强制加入，不自动断开已有控制者。

## 网络边界

账户 API 使用固定 `https://api.nrd.nie.163.com`；信令域限于 `nrd.nie.163.com` 及其子域，动态 TLS 端口仅用于精确 `/socket.io/` polling 路由。网页与原生两层校验协议、主机、端口及路径，拒绝明文、userinfo、危险路径和不受支持地址。

信令采用 Engine.IO 4 / Socket.IO HTTPS polling，禁用升级及 Socket.IO 自动无限重连。原生 WSS 打开明确拒绝：当前实现要求禁止重定向，不能在无法保证该边界的通道上传递认证信息。

原生 HTTPS 保留系统 CA 与主机名校验，设置 `maxRedirects=0`。不得以关闭 TLS 验证、扩大任意域名许可或修改系统代理来处理连接失败。

当房间下发合法公网 IPv4 时，路由地址与证书身份分开处理：URL 使用固定 `nrd.nie.163.com`，IPv4 仅绑定到应用内 DNS 规则；私网、回环和保留地址拒绝。命名信令源直接保留其域名，不修改系统 DNS，参见 [security.ts](../web/src/security.ts)。

polling 使用 HTTP/1.1。命名源保留正常连接池行为，不强制关闭连接；仅共享根域 `nrd.nie.163.com` 使用 `Connection: close`，隔离动态 DNS 规则变更后的旧节点连接。

## 顺序、取消与资源所有权

Engine.IO POST 保持串行，慢 POST 可能影响后续 pong；不能通过并发 POST 或无依据重放绕过。Windows 的 relay candidate 分段也保持 FIFO，参见 [nativePolling.ts](../web/src/nativePolling.ts)。

每次逻辑连接拥有独立的入站信令队列；回调检查当前连接身份，旧 Peer 上未结束的任务不会占住下一连接的队列。参见 [signalQueue.ts](../web/src/signalQueue.ts)。

原生回调同时核对请求实例及页面代际。信令 DNS 添加、删除与销毁串行执行，路由切换前销毁旧 polling 请求并释放 pending 容量；迟到完成不能恢复旧路由或写入新页面。

仅在 JOIN 明确接受后取得房间清理所有权。后续本机校验失败也尝试 LEAVE；未被接受的 JOIN 不清理他人房间。服务端释放成功但本地 DNS 清理失败时只重试本地清理，保留可重试状态，不重复释放服务端房间。

用户取消仍在进行的 JOIN 时，等待请求结果以确认所有权，再正常释放。连接、取消、退出动作由动作门串行执行，不通过并行发起连接掩盖旧清理失败。

媒体输入须同时满足已收到首帧、Peer 已连接、控制通道已打开。失焦、停用控制、取消和断开均释放持有键鼠；无法释放时结束媒体会话，避免继续沿用不确定输入状态。

## 有限握手与信令恢复

握手与恢复仅针对当前已校验的第一个信令端点，没有实现完整多节点轮换。预算由房间配置约束，参见 [signalClient.ts](../web/src/signalClient.ts)：

- 单次握手默认 15 秒，上限 30 秒；重试间隔默认 5 秒，上限 25 秒。
- 初始握手最多两次，总期限为 `2 × 单次期限 + 重试间隔`，最多 85 秒。
- 已接受 control 且持有有效重连 key 后，瞬时 ping timeout / transport error / transport close 才可恢复；每轮最多两次，期限为 `2 × (重试间隔 + 单次期限)`，最多 110 秒。
- 认证拒绝、解析失败、服务端主动关闭及用户退出不进入上述恢复，预算耗尽结束信令并向界面报告失败。

连接每 30 秒检查 key 刷新，未取得 key 或 key 达 300 秒时请求更新；key 仅保存在当前逻辑连接内存，不落盘、不记录日志。

恢复创建新的私有 Socket.IO Manager，丢弃旧 Engine.IO sid、ACK 和写缓存，以重连 key 恢复同一房间。成功时保留现有媒体 Peer；不重发 control、offer 或旧 POST，也不把信令恢复自动视为媒体与输入恢复。

底层 HTTP 连接期限为 15 秒，API / polling 读取期限分别为 30 / 40 秒；网页 HTTP 桥等待 45 秒，给原生结果回传保留余量。ACK 等待另有 10 秒上限，不能将这些不同层的期限混为同一个无限重试预算。

## 凭据与诊断

协议材料由用户在本地密码框显式导入 HUKS，签名通过 HUKS HMAC-SHA256 完成；缺少材料返回 `MATERIAL_MISSING`，不生成替代值。材料不随源码或安装包分发，输入在导入流程中清空；离线签名自检不等于服务端认证通过。

登录 Token、用户 ID 和主控身份使用单个 AssetStoreKit 安全资产，限制大小及字段，设备解锁时可读、禁止同步、不保留卸载数据。启动恢复后读取 UU 设备列表验证；退出删除，业务码 1120 使登录态失效。安全存储失败明确提示，不回退普通文件或 Web Storage。

手机号、验证码、房间凭据及重连 key 不持久化。不得提取官方客户端账号缓存，或把凭据放入 Git、配置、日志与截图；macOS 辅助工具的 Keychain 映射及协作约束见 [AGENTS.md](../AGENTS.md)。

诊断仅保留固定阶段/状态、受限数字、时序与媒体聚合计数，公开服务器元数据只含规范化协议、主机和端口。原生对网页日志再次白名单校验；不输出原始响应、Header、Cookie、SDP、ICE candidate、按键内容或凭据。

界面可用、协议确认与离线检查均不替代画面、鼠标、键盘的实际验收。当前可用范围与失败边界统一见[兼容性与验证结果](兼容性与验证结果.md)，不从静态实现推断鸿蒙实体电脑或反向被控已通过。

## 维护与来源

维护连接流程时应同时检查队列、页面代际、房间所有权、输入释放和上述有限预算；显示名称、平台图标及协议注册类别分别处理，避免外观修改影响安装身份和安全资产。

构建与检查统一使用 [README](../README.md) 的入口。第三方协议复用和图标来源遵守固定版本及许可记录，见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)；临时研究、官方二进制和私人运行证据不随公开源码分发。
